Seven HubSpot theme upload errors I hit, and how to sweep for the whole class

The validator reports one class of error per upload, so you meet the rules by breaking them. Here are the ones that cost me uploads, so they cost you none.

Subscription
Any account with CMS or Content Hub access
Permissions
Developer access and CLI access to the account
Time

Last verified

Short answer

HubSpot will not validate a theme until every rule passes, and it reports one class of error at a time. The errors I hit: a reserved field name (label, body), email template types needing a _page suffix, field IDs that must be unique across the whole theme, text fields not supported in the theme's field file, and mobile being the only valid breakpoint name. When an error names a reserved word, sweep the theme for every reserved word at once.

1. The setup

I built a theme from scratch: fifteen templates, eleven drag and drop modules, and theme settings wired so one color change in the Design Manager repaints the site. It took six uploads to pass validation. The code was not bad. The validator reports a class of error at a time, so every upload surfaced the next one. Here they are in the order I hit them.

2. The seven errors

  1. Field name cannot be label. It is a reserved word. I renamed it across five modules.
  2. email_backup_unsubscribe is not a valid template type. All three email system template types want a _page suffix.
  3. Duplicate field id enabled. Theme field IDs are globally unique. They are not scoped to their group.
  4. Text fields are not supported in the theme's fields.json. My footer copy had to become its own module.
  5. Invalid breakpoint tablet. mobile was the only breakpoint name it accepted.
  6. Duplicate field id, again, inside one module. Nested child fields count too.
  7. Field name cannot be body. Another reserved name.

3. Sweep the class, not the symptom

Number seven is the lesson. When it turned out to be another reserved field name, I stopped fixing the one it named and searched the whole theme for every reserved word at once. The next upload went clean. Six rounds of treating symptoms, one round of treating the class.

hs cms upload src my-theme
# on a reserved-name error, search every field name before uploading again
grep -rn '"name": "\(label\|body\)"' my-theme
  • Keep a list of the errors in the theme's README so the next developer inherits them.
  • Check IDs for uniqueness across the theme, not just within a module.
  • HubSpot requires the system templates, such as 404, 500, password prompt, search results, and subscription pages. Plan for them from the start.
