Stop creating custom timestamp fields: HubSpot already tracks when a record entered each lifecycle stage

Before you build seven custom date properties to track how long people spend in each stage, look at what HubSpot already stamps for you.

Subscription
All tiers for the properties; reports and workflows depend on your tier
Permissions
Any user can view; reports need report access
Time
6 min · Intermediate
Validated
October 11, 2026, 6:00 PM ET

Short answer

HubSpot automatically creates a Date entered property and a Latest time in property for each lifecycle stage, and a Cumulative time in property for re-entries. HubSpot fills them as records move through the stages. Before you add custom date fields for each stage in a journey model, check these first. They need a Professional or Enterprise subscription for the latest and cumulative time properties.

1. Search for "date entered"

Open Contact properties and search date entered. You will see one date and time property per lifecycle stage, named like Date entered "Lead (Lifecycle Stage Pipeline)".

2. Search for "time in"

The matching duration properties are named Latest time in "Lead (Lifecycle Stage Pipeline)" and so on. They hold the total time in seconds the record spent in each stage, so you can filter and report on it. A record currently in a stage has no value for that stage's Latest time in property until it leaves. Its value updates when it leaves.

Example from my portal

In my portal I had this as an example. A journey model with seven stages seemed to need seven custom date fields. The lifecycle timestamps covered the same stages, so no custom fields were needed. You may have something like this.

3. Where this saves work

  • Journey and funnel models. If your stages line up with lifecycle stages, you may not need custom date fields for them. The timestamps already exist.
  • Segments. Filter on Date entered for a stage to list everyone who became a Lead last month.
  • Reports. Time in stage works as a number in custom reports.
Catches

These properties follow the lifecycle stage property. If your team does not keep lifecycle stage current, the timestamps will not move either. See why SQL reports show zero. Also, workflows do not enroll a record based on Latest time in or Cumulative time while the record is still in that stage. Use Lifecycle stage not updated in last x days instead.

Company records have their own lifecycle stage and their own set of these properties. Check the company property list separately.
