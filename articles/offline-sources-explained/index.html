HubSpot 'Offline Sources' is not offline: how to see what created those contacts

A giant Offline Sources number makes attribution look broken. It usually is not. It is a bucket, and two properties tell you what is inside it.

Short answer

Offline Sources is one of the traffic source values HubSpot assigns to a record. It is a bucket for records that did not come from a tracked web source. It does not say how the record was created. HubSpot's knowledge base points to the Record Source property for that, which covers imports, integrations, the mobile app, and records entered by hand. Use the traffic drill-down properties for web detail, and Record Source for the offline detail.

1. What the property is called

The property is Original Traffic Source, with Original Traffic Source Drill-Down 1 and Drill-Down 2 beside it. A matching Latest Traffic Source property tracks the most recent web source. Open Contact properties and search "original source" to see them.

2. See the values

Open the property to see its dropdown options and how many records hold each. In this demo portal most contacts are Offline Sources. They were created by a mock import, so they have no web visit behind them. The internal name is OFFLINE.

Set by HubSpot

HubSpot sets the Original Traffic Source from the first known web source and does not let you edit the drill-down properties by hand. Changing a record's traffic source clears its drill-down values.

3. Find out how the record was created

For web traffic, the drill-down properties give the channel and the specific source. Offline Sources has no web detail, so look at the Record Source property instead. It shows how each record was created, for every object. HubSpot recommends it for this question in place of the Offline Sources value. The steps are in the knowledge base article linked below.

Example from my portal

In my portal I had this as an example. Older records were mostly imports, and newer ones came from a connector and from automatic creation from email and meeting activity. Looking at the drill-downs alone did not show that. You may have something like this.

4. What to do with the answer

  • Mostly imports: add your own source property on the import so you can tell lists apart.
  • Mostly integrations: check whether the app can set a source, or add a workflow that sets one.
  • Entered by hand: report it under its own name instead of Offline Sources, since it is neither an import nor a web visit.
