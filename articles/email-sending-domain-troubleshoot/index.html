Email sending domain won't verify

Most sending domains that won't verify have a DNS record problem. Check the record, the host name and the propagation time before you change anything else.

Short answer

Most DNS changes show up within five hours, and full propagation can take up to 48 hours. If the domain still won't verify, compare each CNAME record in HubSpot with the record at your DNS host. The usual fix is to enter the host name without the root domain, because some DNS hosts add it again and create a duplicated root domain.

1. Find the sending domains

Open Settings, then Content, then Domains & URLs, and select the Email Sending tab. Each domain shows its status. Connect sending domain starts a new one.

Example from my portal

In my portal I had this as an example. Two sending domains showed Not authenticated at the same time,. You may have something like this.

2. Compare the records

On the Verify URLs step, HubSpot shows a banner when it can't connect a record. It groups the problem as a typo, a missing record, or a conflicting record. Open your DNS host and confirm the CNAME records match the host name and values HubSpot gives you. Then select Refresh or check them again in HubSpot.

3. Remove the duplicated root domain

Some DNS hosts add your domain to the end of each record by default. For a DKIM record, that turns hs1-123456._domainkey.example.com into a record ending in example.com.example.com. Enter the host name without the domain, such as hs1-123456._domainkey. Some DNS hosts reject characters such as underscores or hyphens in a CNAME; if yours does, contact its support.

4. Check with Dig

Use a DNS lookup tool such as Dig to check the record at the public DNS level. Set the type to CNAME for an email sending domain. The result should match the value HubSpot provides, which for an email sending domain looks like yourdomain-com.hs[#]a.dkim.hubspotemail.net. or the b variant.
